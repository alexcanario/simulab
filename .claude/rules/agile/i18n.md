# i18n

- The app ships in each locale of the `- UI locales:` line of `CLAUDE.md` (default pt-BR, en) from the first feature; no line, pt-BR, pt-PT, en. The list is read as `references/conventions.md` "App UI languages" says. A feature is not done in one language.
- No hardcoded UI text: labels, titles, tooltips, placeholders, validation and error messages, emails and notifications come from resources.
- One resource set per module: `Resources/<Module>.resx` (neutral, the language of `<NeutralLanguage>` in the root `Directory.Build.props`) plus one `.<locale>.resx` per other listed locale. Access through `IStringLocalizer<T>`.
- A new key is added to the neutral file and to every other listed locale in the same commit. A test fails when a key is missing in a listed locale or a satellite exists for the neutral culture; a file of an unlisted locale is not read.
- Keys are stable English identifiers (`ExamBoards.List.Title`), never the text itself. API error codes are keys as they are (`exam_board.acronym_taken`).
- pt-BR and pt-PT are different texts, not copies: check vocabulary (tela/ecrã, usuário/utilizador, cadastro/registo) and treatment.
- Text with values uses placeholders (`{0}`) and whole sentences. Never concatenate fragments; word order changes per language.
- Plurals and gender get separate keys. Never build them with `+ "s"`.
- Dates, numbers and currency are formatted with the user's culture. Never a fixed format string in the UI.
- Store and transfer instants in UTC; convert to the user's time zone only when displaying.
- Domain and API layers return codes, never translated text. Translation happens at the edge (UI, email renderer).
- Logs and exception messages are English and are never shown to the user.
- The culture comes from the user profile, then the browser, then the first locale of the list. The language switch (visible on every layout) and the supported cultures are the list.
- Sorting and searching text the user sees is culture-aware and accent-insensitive unless the feature says otherwise.
- Adding a language means adding resource files only. If code must change, the abstraction is wrong.
- Screen mockups and validation scripts include one language switch.
- The app manual (`docs/manual/<locale>/`) is updated when the feature ships, in each locale of the `Manual locales:` line of `CLAUDE.md` (default pt-BR).
