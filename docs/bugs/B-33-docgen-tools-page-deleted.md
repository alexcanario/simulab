# DocGen with `tools: false` deletes the tool catalogue page that a test still reads

Technical terms: [glossary](../glossary.md)

## What happens
Found at the ship of F-89 (2026-10-21). Since F-49 (`959b821`, "turn off the DocGen tool catalogue until the app offers a tool") `tools/Simulab.DocGen/docgen.json` has `"tools": false`, but `docs/architecture/tools.md` and its link in `docs/architecture/README.md` are still committed on `main`, and `tests/Simulab.ArchitectureTests/DocGen/ToolCatalogueDocTests.cs` still reads the committed page.
1. Run the declared docs command (`gate.js docs`, which runs `dotnet run --project tools/Simulab.DocGen`) on a tree that matches `main`.
2. DocGen deletes `docs/architecture/tools.md` and the `tools.md` line of `docs/architecture/README.md`, and reports `agile docs GREEN: 2 file(s) changed under docs/architecture/`.
3. Commit those two files and run `gate.js ship`: the suite is RED on `ToolCatalogueDocTests.CommittedCatalogue_MatchesTheToolsInTheProductionAssemblies`.

Evidence: the gate log of the F-89 ship (`agile gate RED: tests failed (Simulab.slnx): Simulab.ArchitectureTests.DocGen.ToolCatalogueDocTests.CommittedCatalogue_MatchesTheToolsInTheProductionAssemblies`). The F-89 ship restored both files from `main` and the next full run was green (4382 tests), so `main` still carries the inconsistency and the next item whose ship runs the docs command meets it again.

Added 2026-10-21 (retro of F-84): it did. At the ship of F-84, `gate.js docs` ran `dotnet run --project tools/Simulab.DocGen` and printed `agile docs GREEN: 2 file(s) changed under docs/architecture/`; `git status` showed ` M docs/architecture/README.md` and ` D docs/architecture/tools.md` (the same two files). They were restored with `git checkout --` and not committed, and the next full run was green (4409 tests). Evidence: the output of that docs run.

## Expected

## Cause
Confirmed 2026-10-21 in the code of `main` (`3707644`).
- Commit `959b821` (F-49) set `"tools": false` in `tools/Simulab.DocGen/docgen.json:6` only to silence the plugin's sync note ("DocGen tool catalogue" missing; `sync.js` reads that switch as the owner's decline). It left the rest of F-49 as delivered in `a58fa16`: the committed `docs/architecture/tools.md` (0 tools) and its link at `docs/architecture/README.md:23`.
- With the switch off, `tools/Simulab.DocGen/DocSet.cs:44` does not generate `tools.md`, so `Program.cs:48` (`GeneratedDocs.Write`) deletes the committed page as stale and `IndexDoc` drops its README line.
- `tests/Simulab.ArchitectureTests/DocGen/ToolCatalogueDocTests.cs:112-119` (`CommittedCatalogue_MatchesTheToolsInTheProductionAssemblies`) reads `docs/architecture/tools.md` unconditionally and never looks at the switch: RED once the page is gone.
- `docs/agile/profile.md:56` still says DocGen "writes `docs/architecture/tools.md` (an empty catalogue while there is no tool)": the text matches the delivered F-49, not the switch.
- No duplicate found: one switch and one test disagree; no business rule is implemented twice.
- Not a function used from several places, so no `Callers:` line.
- Other tests that touch the switch are not affected: `DocSetTests` and `DocGenModelDriftTests` pass explicit `DocGenOptions`, and `TheCommittedOptions_KeepTheComparisonOn` reads only `Entities`/`DataDictionary`.

## Fix
The catalogue stays off (`"tools": false` unchanged); the committed files and the test follow the switch.
1. Delete `docs/architecture/tools.md` and the `- [tools.md](tools.md)` line of `docs/architecture/README.md` (exactly what DocGen writes with the switch off).
2. `ToolCatalogueDocTests.CommittedCatalogue_MatchesTheToolsInTheProductionAssemblies` reads `tools/Simulab.DocGen/docgen.json` through `DocGenOptions.Read`. Switch on: the page must equal `ToolCatalogueDoc.Render(...)` as today. Switch off: the page must not exist and `docs/architecture/README.md` must not link it.
3. `docs/agile/profile.md:56`: say the catalogue is off while the app offers no tool, and that the AI coach turns `"tools"` on in `docgen.json` and commits the first `tools.md` with its first tool.

## Docs

## Regression test
- New `ToolCatalogueDocTests.CommittedFiles_FollowTheToolsSwitch` (reads the real `docgen.json`; switch off: no `tools.md`, no README link; switch on: the page equals the render). Written first and seen RED on `main` (the page is committed with the switch off), GREEN after Fix 1.
- The existing committed-catalogue test is replaced by it (one test, not two reading the same file).
- Check by hand at validation: `gate.js docs` then `git status` shows nothing changed under `docs/architecture/`.

## Decisions
- 2026-10-21: fix side — owner chose "keep the catalogue off" (recommended) over "turn it on again". Reason: F-49 turned it off on purpose to silence the plugin's sync note until the first tool exists; turning it on brings the note back. asked
- 2026-10-21: the test follows the switch instead of being deleted, so the first item that turns `"tools"` on is forced to commit the page. Technical choice, no product impact.
- 2026-10-21: the plugin's sync note itself (it fires again whenever the switch is on and `Program.cs` does not cite `ModelToolAttribute`) is plugin territory, already in the plugin notes of the retro log; not touched here.
