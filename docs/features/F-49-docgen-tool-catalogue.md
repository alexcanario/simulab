# DocGen tool catalogue

## Summary
Since plugin agile@canary 0.0.70, `tools/<App>.DocGen` can also generate `docs/architecture/tools.md`: one row
per tool the app offers to a model, built from a `[ModelTool]` attribute (description, input schema, what it
reaches, permissions, whether it writes, whether it asks first). Simulab does not use this yet — surfaced by
`/agile:sync` (0.0.63 → 0.0.71) as a capability the plugin ships that the project lacks.

## Goal
Prepare the codebase to expose tools to Claude through `IAiGateway.CompleteAsync` (tool use) when a feature
needs them (AI coach, later). Add the infrastructure — `ModelToolAttribute`, DocGen integration, tests — so
tools can be added later without rework.

## Users and use cases
- UC1 A developer decorates a method with `[ModelTool]` to expose it as a tool to the model.
- UC2 `dotnet run --project tools/Simulab.DocGen -- --check` verifies every tool has a description, permissions,
  what it reaches and a unique name; exits 0 if all pass, 1 if any fail.
- UC3 After every feature that adds tools, DocGen regenerates `docs/architecture/tools.md` with the catalogue.
- UC4 A reviewer reads `docs/architecture/tools.md` to understand what the model can do, what permissions each tool
  needs and what it reaches.

## Business rules
- BR1 `ModelToolAttribute` (the attribute that marks a method as a tool) lives in `Simulab.Ai` namespace, copied from
  the plugin template.
- BR2 A tool method must have `[Description]` on the method and on every parameter. DocGen's `--check` fails if missing.
- BR3 Every tool must declare `Permissions` (a string array, possibly `["authenticated"]` for any signed-in user).
  DocGen's `--check` fails if the array is empty or missing.
- BR4 Every tool must declare `Reaches` (a string array naming the APIs, services, tables or queues it touches).
  DocGen's `--check` fails if the array is empty or missing.
- BR5 Tool names derived from the method name (dropping `Async` suffix) must be unique. DocGen's `--check` fails on
  duplicates; an explicit `Name` property can override the derived name.
- BR6 `docs/architecture/tools.md` is generated from every method decorated with `[ModelTool]` in the solution.
  The file exists immediately (initially empty) and lists tools in a table with: name, description, input schema
  (from method parameters), permissions and what it reaches (from the attribute).
- BR7 DocGen's `--check` includes the tools catalogue: `--check` exits 1 when a tool is missing description,
  permissions, reaches or has a duplicate name.
- BR8 An architecture test forbids any assembly outside `Simulab.Ai` from referencing the `Anthropic` package
  (ADR-0001 #37, F-41, BR1).

## Acceptance criteria
- AC1 (BR1) Given the plugin template, when `ModelToolAttribute.cs` is copied to `Simulab.Ai`, then it compiles with
  the right namespace and documentation.
- AC2 (BR2, BR3, BR4) Given a method with `[ModelTool(Permissions = ["read_exams"], Reaches = ["ExamService"])]`
  and `[Description("Gets exam details.")]` on the method and each parameter, when DocGen runs, then no error about
  missing attributes.
- AC3 (BR2) Given a method with `[ModelTool(...)]` but no `[Description]`, when `--check` runs, then it fails with a
  message naming the missing description.
- AC4 (BR3) Given a method with `[ModelTool(Permissions = [])]`, when `--check` runs, then it fails; a method with
  `[ModelTool(Permissions = ["authenticated"])]` passes.
- AC5 (BR4) Given a method with `[ModelTool(Reaches = [])]`, when `--check` runs, then it fails; a method with
  `[ModelTool(Reaches = ["ExamTable"])]` passes.
- AC6 (BR5) Given two methods both deriving to the same name (e.g., both named `GetExamAsync`), when `--check` runs,
  then it fails with a duplicate-name error; one method can override with `[ModelTool(Name = "GetExamDetails")]`.
- AC7 (BR6, BR7) Given one method with `[ModelTool]` fully decorated, when DocGen runs, then `docs/architecture/tools.md`
  is created with a header and a table listing the tool's name, description, input schema, permissions and reaches.
- AC8 (BR6) Given the catalogue has one tool, when `--check` runs, then it exits 0 and the file is up to date.
- AC9 (BR6) Given a new method is added with `[ModelTool]`, when `--check` runs, then it exits 1 (file is stale);
  running the generator updates the file.
- AC10 (BR6) Given all tools are removed, when the generator runs, then `tools.md` becomes empty (only a header
  and empty table) and exits 0 on the next `--check`.
- AC11 Localization: no UI text is added; the missing-key test stays green.

## Decisions
- 2026-09-27 — `ModelToolAttribute` lives in `Simulab.Ai`, not `SharedKernel` — owner; the gateway is the
  right owner; when another module needs tools, it references `Simulab.Ai`.
- 2026-09-27 — F-49 is infrastructure only: no actual tools yet — owner; the AI coach feature (later) will add
  the first ones.
- 2026-09-27 — `docs/architecture/tools.md` is generated immediately even if empty — owner; signals the capability
  is ready; the catalogue appears as tools are added.
- 2026-09-27 — Tool validation on `--check`: description, permissions, reaches are mandatory; names must not duplicate
  — owner; prevents silent gaps (forgetting a field looks the same as making a choice).
- 2026-09-27 — No package change. `Anthropic` SDK remains in `Simulab.Ai.csproj` only (imported by F-41) — technical.

- 2026-09-28 — Build finding: the plugin's DocGen template writes no `tools.md` while there is no tool; Simulab's
  generator (`ToolCatalogueDoc`) writes a header and an empty table instead, as decided above — technical.
- 2026-09-28 — Build finding: `AIFunctionFactory` (Microsoft.Extensions.AI.Abstractions 10.5.1) keeps the method name
  as it is, so the derived name of `GetExamAsync` is `GetExamAsync`, not `GetExam`. BR5 and AC6 hold with that name;
  the catalogue shows what the model really receives — technical.
- 2026-09-28 — Build finding: the catalogue lists input schema per tool in a section below the table (parameters
  table plus JSON schema), as the plugin template does, not as a table column — technical.
- 2026-09-28 — No package added: `Microsoft.Extensions.AI.Abstractions`, which builds the schemas, comes with
  `Anthropic` through `Simulab.Ai`. BR8 was already enforced by `AiGatewayBoundaryTests` (F-41); not duplicated — technical.
- 2026-09-28 — `docs/architecture/Identity/routes.md` regenerated in the same run: `main` had it stale since F-32
  (`GET /api/v1/identity/account-events/mine`) — technical.

## Validation script
No screen changes, no sign-in or language switch. Run from the repository root on `feature/F-49`.
1. `dotnet build Simulab.slnx` → `Build succeeded.` and `0 Warning(s)`.
2. `dotnet test tests/Simulab.ArchitectureTests` → all pass. Vocabulary and forbidden-reference tests include
   `ModelToolAttribute`.
3. `dotnet run --project tools/Simulab.DocGen -- --check` → `docs/architecture is up to date` (tools.md empty but present),
   exit 0.
4. Create `src/BuildingBlocks/Simulab.Ai/Probe.cs` with `[ModelTool(Reaches = ["X"])]` and `[Description("Probe.")]` on a
   public static method (no `Permissions`). Run step 3 → exit 1, `Simulab.Ai.Probe.<method>: no Permissions`.
5. Add `Permissions = ["authenticated"]`. Run step 3 → exit 1 (`tools.md` is stale); run it without `-- --check` →
   `1 file(s) written`; `--check` again → exit 0. Then delete `Probe.cs`, run without `--check` and `--check` → exit 0.
6. Open `docs/architecture/tools.md` in the IDE's Markdown preview. It shows a header and an empty table (ready for tools).
7. Open `docs/agile/profile.md`: the `tools/` section mentions `ModelToolAttribute` and the tools.md catalogue.
