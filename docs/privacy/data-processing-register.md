# Data processing register

Technical terms: [glossary](../glossary.md)

**Draft: not reviewed by a lawyer. This is Claude's reading of the code and of public sources, not legal advice.**

What personal data Simulab processes, why, where it is stored, who processes it and how it crosses borders (LGPD Art. 37, GDPR Art. 30). It was written on 2026-10-09 by F-93 from the code of the `main` branch and from [ADR-0004](../decisions/ADR-0004-data-region-central-us.md), which holds the region decision and the legal basis of each transfer. Every row cites the file it came from. A column that the code does not settle says `not verified` or `none defined`; nothing here claims an encryption, a retention period or a purpose the code does not apply.

Only the Identity module holds personal data today. Catalog and Plans hold none; every entity carries the id of the user who created or changed it (`CreatedBy`, `UpdatedBy`, `DeletedBy`), which is a pseudonymous identifier, listed in the audit row.

Region: every cloud resource of the staging environment is in Azure Central US (`centralus`, United States), except the email service, whose data location is Brazil ([ADR-0004](../decisions/ADR-0004-data-region-central-us.md)). The `local` environment runs on the developer's machine and holds no real person's data. Production does not exist yet.

When a feature adds a processor or a new category of personal data, it adds or changes the row here in the same item. Nothing enforces that yet.
